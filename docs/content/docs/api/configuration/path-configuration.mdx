## Object keys

An object key is built from three parts:

```text
{global prefix} / {route prefix} / {name}
   uploads      /  users/42      / avatar-k3x9m2a7qp.png
```

Each part is declared, not hand-assembled. The library joins them, sanitises
every segment and refuses anything that would escape its folder, so a route
never has to sanitise a filename or invent a random id itself.

```typescript title="app/api/upload/route.ts"
const router = s3.createRouter({
  avatar: s3
    .image()
    .maxFileSize("2MB")
    .middleware(async ({ req }) => {
      const user = await requireUser(req);
      return { userId: user.id };
    })
    .paths({
      prefix: ({ metadata }) => `users/${metadata.userId}`, // metadata is typed
      name: "unique",
    }),
});
// "My Avatar.png" → users/42/My_Avatar-k3x9m2a7qp.png
```

Call `.paths()` after `.middleware()`: the `prefix` and `name` functions then
receive the middleware's output as `metadata`, typed, with no cast.

<Callout type="warn">
  **The default name is the filename.** Without `name: "unique"`, two uploads
  of `photo.jpg` under the same prefix write the same object, and the second
  silently replaces the first. Use `"unique"` unless overwriting is what you
  want, such as a fixed avatar per user.
</Callout>

## `prefix`

The folder a route's keys live under, nested below the global prefix.

```typescript
.paths({ prefix: "documents" })                        // documents/report.pdf
.paths({ prefix: ({ metadata }) => `orgs/${metadata.orgId}` }) // orgs/7/report.pdf
```

- A **string** is a fixed folder. `documents` and `documents/` are the same.
- A **function** is computed per file. Each segment it returns is sanitised
  (`Acme Corp` → `Acme_Corp`). It must not produce an empty segment: a prefix
  of `users/${id}` with an empty `id` is refused, not collapsed to `users`,
  because collapsing it would quietly put the file outside every user's
  folder.

## `name`

The last part of the key.

| `name` | `Q3 report.pdf` becomes | Use when |
| --- | --- | --- |
| `"original"` (default) | `Q3_report.pdf` | The name is meaningful and overwriting is intended |
| `"unique"` | `Q3_report-k3x9m2a7qp.pdf` | Almost always: no upload replaces another |
| `(ctx) => string` | whatever you return, sanitised | You need a specific name or extra folders |

`"unique"` keeps the sanitised filename readable in a bucket listing and adds a
random 10-character base32 id before the extension, so the extension stays
last.

```typescript
.paths({
  prefix: ({ metadata }) => `products/${metadata.productId}`,
  name: ({ metadata, file }) => `${metadata.sortOrder}-${file.name}`,
})
// products/p_123/2-front.jpg
```

A `name` function may return a path with `/` in it to add folders below the
prefix.

## Global prefix

A prefix every route shares, set once on the config:

```typescript title="lib/upload.ts"
const { s3 } = createUploadConfig()
  .provider("cloudflareR2", { /* ... */ })
  .paths({ prefix: "uploads" })
  .build();
```

Every route's keys nest below it: `uploads/users/42/avatar-k3x9m2a7qp.png`.

The global `.paths()` also accepts `generateKey: (file, metadata) => string`,
the part of the key below the prefixes for routes that do not set `name`.
Return the part below the prefixes only; the prefixes are added for you.
Prefer a route's `name`, which receives typed metadata.

## `generateKey`: the escape hatch

When a key does not fit `{prefix}/{name}`, a route can return the whole key
itself. The global and route prefixes are **not** applied.

```typescript
.paths({
  generateKey: ({ metadata }) => `products/${metadata.productId}/cover.jpg`,
})
```

It is still checked like every other key. `ctx` also carries `routeName` and
`globalConfig`, the global `.paths()` settings, if you want to build on the
global prefix.

## Keys are checked, always

Every key a route produces passes through one chokepoint before it is signed:
the default key, the prefix, the name and the output of `generateKey`. It is
the same check the [Python](/docs/integrations/python) and
[Go](/docs/integrations/golang) servers apply, so a key resolves the same way
whichever server answers.

A key is **refused** when it:

- is empty or absolute (starts with `/`)
- contains `?`, `#` or `%`, which change how a key parses in a URL
- contains a control character or an invisible bidi or zero-width character
- has an empty, `.` or `..` segment (`a//b`, `a/./b`, `../b`)
- is longer than 1024 bytes once sanitised (S3's limit is on bytes, and a CJK
  character costs three)

Every other key is **re-sanitised segment by segment**, with the same rules as
the default filename: non-Latin names are kept, other ASCII punctuation becomes
`_`.

```typescript
.paths({ prefix: ({ metadata }) => `orgs/${metadata.orgName}` })
// orgName "Acme Corp", file "Q3 report.pdf" → "orgs/Acme_Corp/Q3_report.pdf"
// orgName "../../admin"                     → refused
```

A refused key fails **that file** with `VALIDATION_FAILED` and a message naming
the key and the rule; the other files in the batch carry on. Nothing is signed
for it, so nothing is written.

<Callout type="info">
  The check stops a key escaping its folder. It cannot tell whether the caller
  may write to that folder. Take ids from your auth middleware, not from client
  metadata.
</Callout>

## Checking a key a client sends back

When a client later names a key (to delete it, or to get a download link),
check it against the same prefix with
[`storage.keys.inScope`](/docs/api/storage/file-operations#ownership-checks):

```typescript
if (!storage.keys.inScope(key, `users/${user.id}`)) throw new Error("Not found");
```

It compares whole segments (`users/1` does not contain `users/10/…`) and
answers `false` for any key with a `..` or empty segment.
