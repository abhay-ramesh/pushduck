## File Management Operations

## List Operations

### Basic File Listing

```typescript
// List all files
const files = await storage.list.files()

// List with options
const files = await storage.list.files({
  prefix: 'uploads/',
  maxResults: 50,
  sortBy: 'lastModified',
  sortOrder: 'desc'
})
```

### Paginated Listing

```typescript
// Get first page
const result = await storage.list.paginated({
  maxResults: 20,
  prefix: 'images/'
})

console.log(result.files)        // FileInfo[]
console.log(result.hasMore)      // boolean
console.log(result.nextToken)    // string | undefined

// Get next page
if (result.hasMore) {
  const nextPage = await storage.list.paginated({
    maxResults: 20,
    prefix: 'images/',
    continuationToken: result.nextToken
  })
}
```

### Filtered Listing

```typescript
// By file extension
const images = await storage.list.byExtension('jpg', 'photos/')
const pdfs = await storage.list.byExtension('pdf')

// By file size (bytes)
const largeFiles = await storage.list.bySize(1024 * 1024) // > 1MB
const mediumFiles = await storage.list.bySize(100000, 1024 * 1024) // 100KB - 1MB

// By date range
const recent = await storage.list.byDate(
  new Date('2024-01-01'),
  new Date('2024-12-31')
)
```

### Directory Listing

```typescript
// List "directories" (common prefixes)
const dirs = await storage.list.directories('uploads/')
// Returns: ['uploads/images/', 'uploads/documents/', 'uploads/videos/']
```

### Async Generator (Large Datasets)

```typescript
// Process large datasets efficiently
for await (const batch of storage.list.paginatedGenerator({ maxResults: 100 })) {
  console.log(`Processing ${batch.files.length} files`)
  // Process batch...
}
```

## Metadata Operations

### Single File Info

```typescript
const info = await storage.metadata.getInfo('uploads/image.jpg')

console.log(info.key)           // 'uploads/image.jpg'
console.log(info.size)          // 1024000
console.log(info.contentType)   // 'image/jpeg'
console.log(info.lastModified)  // Date object
console.log(info.etag)          // '"abc123..."'
```

### Batch Metadata

```typescript
const keys = ['file1.jpg', 'file2.pdf', 'file3.mp4']
const results = await storage.metadata.getBatch(keys)

results.forEach(result => {
  if (result.success) {
    console.log(result.info.size)
  } else {
    console.log(result.error)
  }
})
```

### Specific Metadata

```typescript
// Get individual properties
const size = await storage.metadata.getSize('file.jpg')
const contentType = await storage.metadata.getContentType('file.jpg')
const lastModified = await storage.metadata.getLastModified('file.jpg')

// Custom metadata
const customMeta = await storage.metadata.getCustom('file.jpg')
await storage.metadata.setCustom('file.jpg', {
  userId: '123',
  category: 'profile-image'
})
```

## Reading Files

Read an object's bytes on the server — to parse an upload, generate a
thumbnail, or hand it to another API. These are signed requests to your
bucket, so they work on private buckets.

### As a Stream

```typescript
const file = await storage.download.get('uploads/report.pdf')

file.body          // ReadableStream<Uint8Array> — read it once
file.size          // 1024000
file.contentType   // 'application/pdf'
file.etag          // 'd41d8cd98f00b204e9800998ecf8427e'
file.lastModified  // Date
```

### As Bytes or Text

```typescript
const bytes = await storage.download.bytes('uploads/photo.jpg')  // Uint8Array
const csv = await storage.download.text('imports/contacts.csv')  // string
```

All three throw an `UploadError` with code `NOT_FOUND` when there is no
object at the key.

### Serving a File Through Your Server

`storage.download.response()` returns a web `Response` that streams the object
with its `Content-Type`, `Content-Length`, `ETag` and `Last-Modified`, plus the
`Content-Disposition` and `Cache-Control` you ask for. Return it from any
framework's route handler:

```typescript
// app/api/files/[id]/route.ts
import { storage } from '@/lib/upload'

export async function GET(req: Request, { params }: { params: { id: string } }) {
  const user = await auth(req)
  if (!user) return new Response('Unauthorized', { status: 401 })

  const doc = await db.document.findFirst({
    where: { id: params.id, ownerId: user.id },
  })
  if (!doc) return new Response('Not found', { status: 404 })

  return storage.download.response(doc.key, {
    filename: doc.originalName,   // saved as this name, any Unicode
    cacheControl: 'private, max-age=300',
  })
}
```

`filename` implies `disposition: 'attachment'` (save the file); pass
`disposition: 'inline'` to display it in the browser instead.

<Callout type="info">
  When the file does not need to pass through your server, redirect to a
  [presigned URL with a filename](/docs/api/storage/presigned-urls#download-with-a-filename)
  instead — the browser then downloads straight from storage.
</Callout>

## Copy and Move

Copies happen inside the provider (S3 `CopyObject`); the bytes never pass
through your server.

```typescript
// Copy, keeping the source's content type and metadata
await storage.copy.file('drafts/report.pdf', 'published/report.pdf')

// Copy with new custom metadata (content type and cache headers are kept)
await storage.copy.file('drafts/report.pdf', 'published/report.pdf', {
  metadata: { publishedBy: user.id },
})

// Move = copy, then delete the source
await storage.move.file('tmp/upload-123.jpg', `users/${user.id}/avatar.jpg`)
```

<Callout type="warn">
  `move.file` is not atomic — S3 has no rename. If the copy fails, nothing is
  deleted; if the delete fails, the error is thrown and both keys exist.
</Callout>

## Server-side Upload

Write a file from your server, for example a generated PDF:

```typescript
const url = await storage.upload.file(pdfBuffer, `invoices/${invoice.id}.pdf`, {
  contentType: 'application/pdf',
  cacheControl: 'private, max-age=31536000, immutable',
  metadata: { invoiceId: invoice.id },
})
```

| Option | Stored as |
|---|---|
| `contentType` | `Content-Type`, served back on download |
| `cacheControl` | `Cache-Control`, served back on download |
| `metadata` | `x-amz-meta-*` custom metadata |
| `onProgress` | — called at the start and end of the upload |

## Ownership Checks

Before acting on a key a client sent back (delete this file, sign a download
for that one), check that it lies inside the caller's folder:

```typescript
export async function DELETE(req: Request) {
  const user = await requireUser(req)
  const { key } = await req.json()

  // The same prefix the upload route used: .paths({ prefix: ({ metadata }) => `users/${metadata.userId}` })
  if (!storage.keys.inScope(key, `users/${user.id}`)) {
    return new Response('Not found', { status: 404 })
  }

  await storage.delete.file(key)
  return new Response(null, { status: 204 })
}
```

`inScope(key, prefix)` compares whole segments, so `users/1` does not contain
`users/10/a.png`, which `key.startsWith(prefix)` gets wrong. It sanitises the
prefix's segments the way `.paths()` does, and it fails closed: it answers
`false` for a key with a `..` or empty segment, for any key pushduck would not
have produced, and for a prefix that does not resolve, such as `users/` built
from a missing id.

| `storage.keys.inScope(key, prefix)` | Result |
|---|---|
| `("users/1/a.png", "users/1")` | `true` |
| `("users/10/a.png", "users/1")` | `false` |
| `("users/1/../2/a.png", "users/1")` | `false` |
| `("users/1", "users/1")` | `false` (the folder itself) |
| `("users/1/a.png", "users/")` | `false` (unresolvable prefix) |

It is a pure function: no request reaches the provider.

## Delete Operations

### Single File Delete

```typescript
const result = await storage.delete.file('uploads/old-file.jpg')

if (result.success) {
  console.log('File deleted successfully')
} else {
  console.log('Delete failed:', result.error)
}
```

### Batch Delete

```typescript
const keys = ['file1.jpg', 'file2.pdf', 'file3.mp4']
const result = await storage.delete.files(keys)

console.log(`Deleted: ${result.deleted.length}`)
console.log(`Failed: ${result.errors.length}`)

// Check individual results
result.errors.forEach(error => {
  console.log(`Failed to delete ${error.key}: ${error.message}`)
})
```

### Delete by Prefix (Folder-like)

```typescript
// Delete all files with prefix
const result = await storage.delete.byPrefix('temp-uploads/')

console.log(`Deleted ${result.deletedCount} files`)

// With options
const result = await storage.delete.byPrefix('old-files/', {
  dryRun: true,        // Preview only, don't delete
  batchSize: 500,      // Process in batches
  maxFiles: 1000       // Limit total files
})

if (result.dryRun) {
  console.log(`Would delete ${result.totalFiles} files`)
}
```

## Validation Operations

### File Existence

```typescript
// Simple existence check
const exists = await storage.validation.exists('file.jpg')

// Existence with metadata: FileInfo, or null when missing
const info = await storage.validation.existsWithInfo('file.jpg')
if (info) {
  console.log('File size:', info.size)
}
```

`exists` returns `false` only when the provider answers **404**. A **403**
throws an `UploadError` with code `STORAGE_ACCESS_DENIED` instead of returning
`false`: S3 and R2 answer 403 rather than 404 for a missing object when the
credential lacks `s3:ListBucket`, so a 403 cannot tell "missing" from "this
credential cannot read the bucket". Grant `s3:ListBucket` on the bucket and
missing objects come back as `false`.

### File Validation

```typescript
// Validate single file
const result = await storage.validation.validateFile('image.jpg', {
  max: "5MB",
  types: ['image/jpeg', 'image/png'],
  min: "1KB"
})

if (result.valid) {
  console.log('File is valid')
} else {
  console.log('Validation errors:', result.errors)
}

// Validate multiple files
const results = await storage.validation.validateFiles(
  ['file1.jpg', 'file2.png'],
  { max: "10MB" }
)
```

### Connection Validation

```typescript
// Test S3 connection and permissions
const isHealthy = await storage.validation.connection()
console.log('S3 connection:', isHealthy ? 'OK' : 'Failed')
```

## Type Definitions

```typescript
interface FileInfo {
  key: string
  size: number
  contentType: string
  lastModified: Date
  etag: string
  metadata?: Record<string, string>
}

interface ListFilesOptions {
  prefix?: string
  maxResults?: number
  sortBy?: 'key' | 'size' | 'lastModified'
  sortOrder?: 'asc' | 'desc'
}

interface ValidationRules {
  max?: string | number
  min?: string | number
  types?: string[]
  requiredMetadata?: string[]
}

interface StoredObject {           // storage.download.get()
  body: ReadableStream<Uint8Array>
  size: number
  contentType: string
  etag: string
  lastModified: Date
}

interface DownloadResponseOptions { // storage.download.response()
  disposition?: 'inline' | 'attachment'
  filename?: string
  cacheControl?: string
}

interface CopyFileOptions {         // storage.copy.file()
  metadata?: Record<string, string>
}

interface UploadFileOptions {       // storage.upload.file()
  contentType?: string
  metadata?: Record<string, string>
  cacheControl?: string
  onProgress?: (progress: UploadProgress) => void
}
```
